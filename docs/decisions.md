# 技术与产品决策

| 编号 | 决策 | 状态 | 可逆方式 | 依据 |
|---|---|---|---|---|
| D01 | 使用微信原生小程序与 TypeScript | 已确认 | 页面层可迁移，领域层保持纯 TypeScript | 用户确认方案 A；V0.2 优先建议原生实现 |
| D02 | 运行时代号使用 `travel-planner`，不作为正式品牌 | 已确认 | 通过品牌配置替换标题、图标、文案和主题 token | 正式名称和视觉素材后续提供 |
| D03 | 核心计算不依赖微信运行时 | 已确认 | Repository 和页面适配器之外均可独立复用 | 需要独立测试金额、时间和结算 |
| D04 | 金额统一保存为人民币整数分 | 已确认 | 首版不支持混合币种；未来通过 Money 值对象扩展 | 避免浮点误差并保证分摊守恒 |
| D05 | 默认时区为 `Asia/Shanghai` | 开发默认值 | 每个 Trip 可保存自己的 timezone | V0.2 国内单时区优先建议 |
| D06 | 使用 Repository 接口隔离本地与云仓储 | 已确认 | 替换实现而不修改领域服务 | 当前无云环境但需要可运行和后续多人持久化 |
| D07 | 无云配置时进入明确标识的隔离演示模式 | 已确认 | 配置有效云环境后切换 CloudRepository | 本地存储不能冒充跨设备共享 |
| D08 | 外部地图缺失时使用手工地点与交通数据 | 已确认 | 配置 MapProvider 后启用搜索和估算 | 不伪造路线及实时信息 |
| D09 | 新疆案例作为独立 seed/fixture | 已确认 | 可新增其他案例包，不改通用模型 | 防止写死三人、新疆或自驾 |
| D10 | 预订、预算与实付分对象保存 | 已确认 | 不允许通过 UI 合并为单一状态 | 已订/已购不等于已支付 |
| D11 | Vitest 作为纯 TypeScript 核心测试运行器 | 开发默认值 | 测试契约稳定时可替换 runner | 支持 Node 环境快速红绿循环 |
| D12 | 首轮视觉使用中性设计 token | 开发默认值 | 品牌配置统一替换 | 正式视觉参考尚未提供 |

“开发默认值”不是用户既有偏好，只是为继续实现采用的可逆选择。
