## 新疆案例数据边界

| 数据类别 | 导入行为 |
|---|---|
| 已预订酒店、已购买门票 | 写入 Booking 状态，不创建 Expense |
| 房价、票价、油费与过路费 | 写入预算及来源，按确定性区分明确、推导、待复核 |
| 当前路线、原后半程、天气备选 | 建立独立 PlanVersion |
| 原文“可行”等结论 | 作为来源文字，系统重新运行规则检查 |
| C01-C10 | 建立 ConflictRecord，不自动确认候选值 |
| 付款人、退款、转账 | 原文缺失，保持为空 |
| 三人、新疆、自驾、坦克300 | 仅属于 fixture，不成为通用默认值 |

## 当前未接通能力

| 能力 | 原因 | 本轮替代 |
|---|---|---|
| 微信真实登录与云端多人共享 | 尚无微信云环境配置 | 本机演示身份与权限过滤 |
| 可对外访问的分享链接 | 需要云端身份和凭证校验 | 本机分享预览，不生成真实链接 |
| 地图地点搜索和路线估算 | 尚无地图服务配置 | 手工地点、距离和耗时 |
| 酒店、票务、价格自动获取 | 未确认可用且允许的接口 | 用户手工录入并保存来源 |
| 支付和自动转账 | 首版明确排除 | 记录线下付款和确认状态 |
| 消息与到期推送 | 尚未接入通知能力 | 打开应用时显示到期待办 |
| 真机验证 | 需要实现后由实际设备运行 | 开发者工具验证后单独报告 |
